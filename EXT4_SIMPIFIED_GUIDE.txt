FORMAT A BLOCK DEVICE WITH LUKS2 and EXT4


This guide is based on the original FSLUKS and Extended guide which and also adds in the new ext4 parts.

However, it will skip over the CLI parts because those have been explained in the old guides. It is expected that the ability to mount and unmount the LUKS system can be done with GUI. It also will skip over any parts which were specific to exfat like clustering.

WHY USE EXT4 OVER EXFAT?

The use of exfat historically was related to Windows use. It has serious limitations such as how deeply nested folders can be (which can occur when you create new categories or files are in transit). The most modern technology is needed. Also linux filesystems can create symlinks. While some space is wasted in the allocation this may result in increased speeds when copying backups. Migration away from exfat just takes time because data has to be moved and all drives need to be reformatted. Additionally the amount of percentage alocated to the EXT4 table should vary based on size of disk and need. Most of all exfat when formatted on Linux is still not compatible with Windows anyway. So this truly makes it not actually needed anymore. No need to worry about sector size. If you ARE concerned with the percentage wasted by EXT filesystems, then you can just write a compressed archive directly to the block device with no partition table anyways.

IDENTIFY BLOCK DEVICE

Insert the drive, ensuring all data on the drive is ready to be lost, and ensure the LUKS and ther drive itself was not automounted.

lsblk

Properly identify what device it is: /dev/sdx

If it was automounted (say in Cinnamon), then have to unmount it first but not power it down. With sudo umount on that block device if needed.

*This guide will refer to the hypothetical device as /dev/sdx, but in most cases is more likely sdb,c,or d. Make sure you don't select the internal drive which has your Linux OS on it. Or any other internal drive or other device. Unplug all devices which aren't needed at the time.


WRITE A NEW GPT PARTITION TABLE ON THE DEVICE

sudo fdisk /dev/sdx

type g to create gpt partition

type n to add new partition.

It will walk you thorough defualts of start and endpoint.

Partition number, favor the lowest (1)

Start, favor the lowest (was 2048 but may vary)

End, favor the highest if not planned to be a multi partition disk.

If there's already a LUKS signature from the previous setup, say YES to remove it.

Now type w to write to the disk. Now the disk has a new partition table.

Remember the date that the table was created so that you can note this on the disk.

lsblk and you'll see the new partition.

*The guide will refer to the hypothetical new partition as /dev/sdx1, although you aren't actually limited to one partition.


APPLY LUKS2 ENCRYPTION

Set up the LUKS before formatting any partition because then no need to unmount, although the order doesn't technically matter.

sudo cryptsetup luksFormat --type luks2 /dev/sdx1

(Are you sure?)
YES

Enter the passphrase:
password


OPEN THE ENCRYPTED PARTITION FOR FORMATTING

sudo cryptsetup -v luksOpen /dev/sdx1 openDrive

Asks for password. If you enter the password the partition is decrypted

The "openDrive" can be named whatever you want, it goes into the /dev/mapper folder.


CONSIDERING PERCENTAGE OF EXT4
You need to specify the percentage use to the EXT4. The default is 5%, and the lowest I have tried is 1%. If the drive is a huge mass storage drive above 4TB then probably 1%. For 1 or 2 TB drives, it may be beneficial to have more percentage such as 2 or 3% if it can be spared. For small devices 5% may actually be able to be done like on a flash drive.

*This hypothetical amount will be shown as <PERCENTAGE>

Just a number 1 to 5, do not add a percent sign.



FORMAT THE OPEN LUKS PARTITION

sudo mkfs -t ext4 -m <PERCENTAGE> -L NAME_OF_VOLUME /dev/mapper/openDrive

Remember this percentage so that you can add this to the info file about your partition.


CLOSE THE ENCYPTED DRIVE

sudo cryptsetup luksClose openDrive



GIVE PERMISSIONS

Open the partition and enter the password on the GUI so it shows up in /media. If not able to do this then the CLI section will explain how to mount without GUI.

While the GUI is open, you can also add a text file specifying the percentage and the date of creation. Keeping track of this info helps keep all data fresh. It is important especially that the partition table is kept fresh especially on magnetic drives.


cd /media/USERNAME

Now give permissions to the folder which has the same name as the partition.

sudo chmod -R 777 NAME_OF_VOLUME



SAFELY EJECT ON GUI

Done, fresh partition to work with.

Don't forget to add info file of date and percentage allocation. Best to track on the disk itself rather than externally. Or with a written label.
